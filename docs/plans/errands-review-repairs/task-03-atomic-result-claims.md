- Keep the current errand row as authority for its latest result. Add `result_revision` (opaque UUID, assigned whenever result content/kind is replaced, including cancellation), and `parent_admission_generation` (monotonic integer). Backfill a stable UUID per existing nonempty result. Claims use revision, not mutable CAS version; replacement always gets a new UUID.
- Use one private task-scoped SQL guard for result writes, claims/releases, parent-to-child admission reservation/decision and prepared deletion admission. Before gated reads, PostgreSQL takes `pg_advisory_xact_lock(hashtextextended('errands:' || taskID, 0))`; SQLite reserves its writer using the established `UPDATE tasks SET id = id WHERE 0` pattern from `internal/db/taskhierarchy.go`. No new guard table is needed. All participating writers use the same key and lock order, followed by affected errand rows in sorted ID order. Keep existing task/hierarchy admission locks at their established outer boundary; do not acquire them from inside this guard. Never hold SQL locks across external I/O. Migrate every participating writer to enforce a phantom-free snapshot and test with independent connections.
- Each child parent-prompt admission increments its `parent_admission_generation` only in the transaction recording a positively accepted successor. A durable pre-dispatch reservation fences that child until submission/turn evidence proves acceptance or refusal. Unknown admission keeps the fence and blocks release of older claims for that child. The decision transaction takes the guard, updates the generation and supersedes old pending results on acceptance; on definite refusal it clears the fence without increment. Retry from existing submission evidence; missing evidence is not refusal. Initial, queue, Send Now and fallback admissions all use this seam.
- A claim captures `(errand_id, result_revision, parent_admission_generation, claim_token, route)`. A proved abort releases only the exact matching revision/token/route while the generation remains equal and no unresolved parent admission exists. If generation advanced, mark the old claim superseded/discarded, never pending; if the revision or token changed, do not touch the replacement. A pending abort blocked by an unresolved admission is retried when the admission resolves. User-origin follow-ups do not advance this generation or supersede the result.

Implement internal `ClaimResults` with the transaction and immutable snapshot contract in the shared design. Introduce the guard helper, revision/admission fields and await-attempt tables in compatible migrations, including every insert/select/scanner/update. The same guard must serialize existing result writes and parent admission state; a method unused by real writers is not acceptance. Do not hold SQL across provider I/O. Backend composition/await uses committed snapshots; remove pending-result text from `fillAwaitResult`. Perform all fallible projection and assembly before committing where possible. Retain the known token for ambiguous commit readback; never return a fabricated empty success. Public tool arguments remain unchanged.

`Errand.ParentAdmissionGeneration` is persisted in every row insert/select/scanner with a replayable default-zero migration. Generic creation rejects an injected generation; generic CAS cannot advance/reset it. Create, Update, ClaimResults, reservation, decision, release and abort all use the same private task SQL guard. Update locates the immutable stored task before locking and preserves the established full-row-write compatibility that ignores attempted immutable field changes.

Repository APIs for the next worker:

- `ReserveErrandParentAdmission(ctx, models.ErrandParentAdmission) (models.ErrandAdmissionReservation, error)`: identity binds task, actual parent/errand, trusted sender, turn and submission. Only a newly committed parent-origin reservation returns `Created=true`; replay returns `Created=false` and its retained `State`. A replayed reservation is not permission to redispatch. Competing unresolved identities are rejected. User-origin calls are no-ops and do not advance generation.
- `DecideErrandParentAdmission(ctx, admission, models.ErrandAdmissionState) error`: accepts only accepted/refused/unknown evidence for that exact reservation. Accepted advances generation once, supersedes the preceding pending result and preserves cancellation or an already-settled exact successor. Refused clears the fence without advancing generation. Unknown retains it. Terminal contradictions and changed turn/sender identity are rejected. Decision and deferred-release retry share one transaction, including rollback on write failures.
- Unchanged `ClaimResults(...) ([]*models.Errand, error)` now retains immutable claim ownership in `errand_result_claim`/`errand_result_claim_item`: errand, revision, captured generation, token and route. Token replay cannot claim a replacement or change the candidate set/owner/route. An unchanged exact claim supports idempotent readback; uncertain/offered/aborted/received await attempts cannot acquire/replay claims. Unresolved admission blocks new claims. Candidate mismatch, duplicate ID or a second-write SQL fault rolls back the whole batch and its receipts/attempt items.
- `ReleaseErrandResultClaims(ctx, taskID, parentID, []models.ErrandResultClaim) ([]*models.Errand, error)` releases only exact non-await receipts. Wrong revision/generation/token/route/parent cannot release a replacement. A generation advance supersedes the old claim, never makes it pending. An unresolved reservation persists `release_pending`; resolution retries it transactionally. Legacy generic CAS release also consults these receipts/fences instead of bypassing them.
- `AbortAwait(ctx, taskID, parentID, token) ([]*models.Errand, error)` commits an aborted tombstone even before a delayed claim, atomically releases matching items or persists deferral, and rejects a received attempt or foreign ownership. Generic await release fails closed without a committed abort. Wire the existing service/handler error paths to this API in the next integration packet; current compile compatibility is not end-to-end outcome acceptance.

Replayable storage also includes `errand_parent_admission`, `errand_await_attempt` and `errand_await_attempt_item`.
