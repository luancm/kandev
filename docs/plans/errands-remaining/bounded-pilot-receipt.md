# Bounded Errands pilot: 2026-11-15

The pilot established useful review, explicit follow-up, a small implementation, cancellation and truthful recovery after an interrupted command. Initial unassisted Luna investigation failed to use an available native tool; one explicit tool hint resolved that case. No production defect requiring a new repair was demonstrated. This is bounded evidence for the tested Codex ACP models, not universal provider certification or approval of the separate performance tradeoff.

The disposable instance ran production build `42650bd9d25802f328e45ccf9937c93620f39a65`, whose production source is unchanged from `90aaec3aee`. Readiness, embedded assets and actual model application were checked. Parent and reviewer used `gpt-6.1-sol`; investigation and implementation used `gpt-6-luna`, with fallback disabled. Private data, provider homes and a five-file Python fixture were isolated from the main instance. The fixture required positive built-in integers and `attempt < max_attempts`; existing assertions were preserved.

## Recovery and inspection boundaries

The restart retained the conversation without claiming that uncertain work had succeeded. In practical terms, the user can inspect the interrupted Errand, but this observation does not demonstrate safe continuation of that work. No replacement child or original-command retry was sent.

Completed-conversation inspection restored workspace infrastructure for files/Git/terminal consumers without launching a child agent or dispatching work. Two workspace-only allocations were later reclaimed. The API execution ID reflects current operational inventory; the durable native identity and exact completion receipt remained intact. An ordinary parent terminal was separately retained for reconnect and exited during the crash. The completion design now uses the precise existing requirement: inspection does not launch an agent or dispatch work.

The operator made one restart sequencing error. After old process identities were absent and socket inspection showed no old listener, an extra raw bind without `SO_REUSEADDR` failed with `EADDRINUSE`. The tool batch incorrectly launched the prepared restart despite that failed command. Later evidence showed `TIME_WAIT`, but its presence at the failed-bind instant was not captured. The preflight gate did not pass, its exact cause remains unproven, and the run was not repeated to erase it. The retained evidence supports the observed recovery outcome with this limitation; it does not establish a fully passed restart procedure.

## Decision and remaining work

Use Errands for an explicit bounded question, fixed-patch review or small change with file ownership and a named acceptance check. Supply sufficient context and tools guidance where the model needs it. Known background commands remain direct process jobs. This pilot does not justify broader autonomous routing, more orchestration features or a whole-feature rewrite.

The [performance receipt](../errands-simplification/ordinary-header-verification.md) remains a separate open release gate: phone first-switch p95 is 121.496 ms over its unchanged limit, phone retained-heap cost is about 0.801 MiB by medians, and desktop switching has a measured fixed cost despite passing its variability gate. Preserve those observations and the earlier failed cohort. The next decision is a justified acceptance budget or a concrete performance hypothesis with a bounded proving check, not another unchanged run until the numbers pass.
